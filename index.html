PARKEE · CS initiative

PARKEE CS HUB / CS Inbox Hub

01

Why I built it

Managing seven service numbers across different brands makes it difficult to keep track of conversations, follow-ups, and SLA performance. I designed one workspace so the team can monitor each source while keeping brand conversations separate.

What I built

An inbox interface for Taptalk, Wappin, and other WhatsApp sources, with ticket labels, status, ownership, SLA reporting, and integration settings. The screenshot shows a demo interface that is not connected to the APIs.

Value for the team and company

Designed to give the team one place to review incoming work and prioritize follow-ups, while providing a consistent approach to service oversight across brands. The demo provides the foundation for API integration and day-to-day use.

PARKEE · CS initiative

Customer Service Performance Dashboard

02

Why I built it

Ticket volume and service quality need to be reviewed together. I built this dashboard to turn operational records into a clear view of workload, complaints, and resolution performance, so team discussions have a common reference.

What I built

A monitoring dashboard with ticket and complaint summaries, FCR, channel and agent filters, year-over-year views, and reconciliation. It brings key service measures into a format that managers can review and use for follow-up.

Value for the team and company

The team can see where work is concentrated and which issues need attention. Managers have a clearer basis for coaching, workload allocation, and staffing discussions. The company gains a more structured way to review service quality and decide which operational issues to address first.

PARKEE · CS initiative

Refund Monitoring & Data Quality

03

Why I built it

Refund cases span several products and require coordination between teams. I needed a clear way to see outstanding cases, check the source data, and distinguish case closure from actual refund completion.

What I built

A dashboard that brings five refund categories into one monitoring flow, with case status, date and location filters, reasons, responsible contacts, data-quality checks, and CSV export.

Value for the team and company

CS can identify cases that still need follow-up and give customers updates based on a shared record. Clear status and ownership make handovers easier. For the company, traceable records and duplicate checks support more careful coordination and review of refund handling.

How I approach improvement.

Start with the service problem, make the data understandable, and connect the result to a decision the team can take.
